Gym Plan B · Demo app map

From “machine busy” to a ranked swap

A compact guide to the app’s core action: how a tap becomes a same-muscle-region recommendation, and where to start when you want to change it.

Snapshot of commit 452df25 · React + Vite + TypeScript · local demo only · open this file directly in a browser; it needs no server.

What the app does

Gym Plan B is a proof-of-concept for the moment a gym machine is taken. Instead of abandoning the exercise, the user says the machine is busy and gets a ranked list of substitutes that train the same muscle group and target region. The user chooses one, and it replaces that slot in the session.

The main pieces are the session state machine (src/lib/session.ts), the recommendation engine (src/lib/recommendation.ts), and the mobile screens in src/screens/. The catalog comes from a read-only Supabase table, with a bundled 26-exercise seed as the offline fallback.

One action, end to end

Action User taps “Machine busy — swap exercise” on the check sheet, then “See suggested swaps.”

Check screen src/screens/CheckScreen.tsx onBusy is the entry point.
→
Session state src/lib/session.ts + src/App.tsx OPEN_BUSY → OPEN_ALTERNATIVES.
→
Recommendation engine src/lib/recommendation.ts rankAlternatives(base, all): hard filter, then 80/20 score.
→
Ranked result + cards ReplacementListScreen.tsx ExerciseOptionCard.tsx: reason, image, tag.
Data source: loadExercises() in src/data/exercises.ts reads the Supabase exercises table or falls back to src/data/seed.ts. Both feed the same engine; no AI model runs at request time.

Reference route

This is a reference route prepared from the finished code, not a claim that a live guided tour was completed. Use it to reopen the thread later.

  1. Start at the user’s decision.

    Open src/screens/CheckScreen.tsx and search for Machine busy. The second button calls onBusy. That prop is wired in src/App.tsx to dispatch OPEN_BUSY.

  2. Follow the state, not just the screen.

    In src/lib/session.ts, find OPEN_BUSY and OPEN_ALTERNATIVES in sessionReducer. In src/App.tsx, the alternatives branch calls rankAlternatives(current, exercises) inside a useMemo, then renders ReplacementListScreen.

  3. End at the rule and the visible result.

    In src/lib/recommendation.ts, read rankAlternatives: the eligible filter is the hard region constraint; the score is 0.8 * movement + 0.2 * type; only the best same-family/same-pattern candidate gets recommended = true. The cards are rendered by ExerciseOptionCard.tsx.

To change this, start here

  • Change the ranking weights: src/lib/recommendation.ts — search for 0.8 * movement and the three movement constants at the top.
  • Add or tighten the hard filter: rankAlternatives in src/lib/recommendation.ts — the eligible filter checks muscleGroup, targetRegion, and classified.
  • Change the list or empty state: src/screens/ReplacementListScreen.tsx — the ranked.length === 0 branch and the “Show more” controls.
  • Change the card copy: src/lib/explain.ts (reasonFor, differencesFor) and src/components/ExerciseOptionCard.tsx.
  • Change the session flow: src/lib/session.ts — actions and the reducer; src/App.tsx maps phases to screens.
  • Change the chest approximation: src/lib/muscleMapMapping.ts and src/components/MuscleFigure.tsx. MuscleMap 1.1 has no upper/middle chest path, so the mask is approximate and labeled “(approx.)”; keep that honesty if you replace it.
  • Change the catalog: src/data/seed.ts and supabase/seed.sql; re-run the seed in the new Supabase project.

A practice to reuse

Put the hard constraint before the score, and test the rule that is easiest to fake. In this app, the region filter runs before the 80/20 ranking, and src/lib/recommendation.test.ts checks that only same-region exercises enter, that needs-review rows never appear, and that a different movement style can never be “Recommend.” That kept an AI-drafted classification table from quietly turning into a confident-sounding but wrong answer.

The same pattern transfers to other agent-assisted builds: define the observable rule, put it in one pure function, then give the agent a failing case to protect. When a library cannot support the precision you wanted — here, chest sub-regions in MuscleMap — degrade to the supported unit and label the approximation instead of inventing detail.
